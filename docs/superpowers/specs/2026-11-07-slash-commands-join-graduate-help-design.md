# v3: `/join`・`/graduate`・`/help` スラッシュコマンド 設計

日付: 2026-11-07

## 目的と背景

サークル用 Discord Bot を v2（Python / discord.py、`C:\Users\sinco\MPCman_v2\mpcman.py`）から v3（C# / .NET 10 / Discord.Net）へ作り直している。
最初の目標は、v2 のテキストコマンド `$join` と `$graduate` を **スラッシュコマンド** として移植し、あわせてコマンド一覧を返す `/help` を追加すること。

スラッシュコマンドにすることで、v2 が必要としていたメッセージ本文の読み取り（特権 Intent の Message Content）が不要になる。

### v2 の現状の挙動（参考）

- `$join`: 発言者のロールが `@everyone` のみなら「部員」ロールを付与。何か1つでもロールを持っていれば拒否。
- `$graduate`: 「部員」を持つ人のみ実行可。「部員」を外し「OB」を付与。
- 結果はメンション付きでチャンネルに公開投稿。ロールは名前で検索。

## ゴール

- `/join`: 「部員」ロールを持っていないメンバーなら誰でも「部員」を付与する。
- `/graduate`: 「部員」を持つメンバーの「部員」を外し、「OB」を付与する。
- `/help`: Bot のコマンド一覧を、実行した本人にだけ表示する（エフェメラル）。
- 機能に必要な権限を README.md に記載する（CLAUDE.md のルール）。

## 非ゴール

- v2 のその他の機能（`$mpcman`、`$mpclogo`、`$hello`、`$clear`、参加時のあいさつ）の移植。今回はやらない。
- 複数サーバーでの利用、グローバルコマンド登録。
- データベースなどの永続化。

## アンチゴール（動いても失敗とみなすもの）

- 特権 Intent（Server Members / Message Content / Presence）を必要とする作りになること。
- 処理の途中で失敗して、メンバーが「部員」も「OB」も持たない状態になること。
- 断りやエラーの返信がチャンネルに公開され、チャンネルが流れること。

## コマンド仕様

| コマンド | 説明文（`/help` とコマンド候補に表示） | 実行できる人 |
|---|---|---|
| `/join` | 部員のロールが付与されます | 誰でも |
| `/graduate` | 部員からOBになります | 誰でも（「部員」がなければ断る） |
| `/help` | コマンド一覧を表示します | 誰でも |

コマンドはサーバー内でのみ使える（DM では使えない）。引数はどれもなし。

### `/join`

- 「部員」を持っていない → 「部員」を付与し、**公開**で返信:
  `{メンション}へサーバーの利用権限を付与しました。これからよろしく！`
- 「部員」をすでに持っている → **本人にだけ**返信:
  `あなたは既に利用権限を持っています！`
- 他のロール（OB、ブースターなど）の有無は判定に使わない。OB が実行した場合も「部員」を付与し、「OB」はそのまま残す。

### `/graduate`

- 「部員」を持っている → 「部員」を外して「OB」を付与し、**公開**で返信:
  `{メンション}は卒業しOBとなりました。これからもよろしく！`
- 「部員」を持っていない → **本人にだけ**返信:
  `そのコマンドを使用する権限がありません！`
- すでに「OB」も持っている場合でも、「部員」を外して成功扱いにする。
- 「部員」の削除と「OB」の付与で、どちらか片方だけが成功した状態を残さないこと（アンチゴール参照）。実現方法は実装者に任せる（例: ロールを1回の API 呼び出しでまとめて更新する）。

### `/help`

- **本人にだけ**返信する。
- 一覧は手書きせず、登録されているスラッシュコマンドの名前と説明文から自動で作る（コマンドを追加しても一覧が古くならないようにするため）。
- 表示例:

```
/join — 部員のロールが付与されます
/graduate — 部員からOBになります
/help — コマンド一覧を表示します
```

### 共通のエラー処理

- 設定されたロール名がサーバーに見つからない、または Bot の権限やロールの並び順が足りずにロール操作が失敗した場合:
  - 本人にだけ返信する（例: `Botの設定に問題があり処理できませんでした。管理者に連絡してください。`）
  - 原因がわかる内容をログに出す。

## 構成

### 採用したアプローチ

**Discord.Net の InteractionService を使い、コマンドをモジュールクラスのメソッドとして書く。**

検討した案:

- **A. InteractionService（採用）**: `[SlashCommand]` 属性でコマンドを定義する。Generic Host の DI にそのまま乗る。登録済みコマンドを取得できるので `/help` の自動生成が簡単。コマンドの追加はメソッドを足すだけで済む。
- **B. `SlashCommandBuilder` と `switch` で自前で振り分ける**: 仕組みは単純だが、コマンドの定義と処理が別の場所に分かれる。`/help` の一覧も手で保守する必要がある。
- **ライブラリを NetCord に替える案**: Generic Host との統合は優れているが、まだ 1.0 のベータ版（2026-11 時点で 1.0.0-beta.29）。サークル Bot は後輩に引き継がれる前提なので、安定版で日本語の情報が多い Discord.Net を続けて使う。

ユーザーは A を選択した。

### 決まっていること

- ライブラリ: Discord.Net（既に参照済みの 3.20.2）。
- ホスト: 既存の .NET Worker（Generic Host）。今の `Worker.cs`（1秒ごとにログを出すだけのループ）は、Bot の接続とコマンド処理を担う形に置き換える。
- コマンドは **ギルド（サーバー）コマンドとして、設定された1つのサーバーにだけ登録する**（登録がすぐ反映されるため）。
- Gateway Intents は `Guilds` のみ。特権 Intent は使わない。
- ロールの判断（付与するか、拒否するか、どのロールを足し引きするか）は、Discord に依存しない小さなクラスに分け、Discord に接続せずに単体テストできるようにする。
- 設定（`appsettings.json` と環境変数・ユーザーシークレット）:
  - Bot トークン: リポジトリには置かない。開発時はユーザーシークレット（`UserSecretsId` は設定済み）、Docker では環境変数で渡す。
  - サーバー ID
  - 部員ロール名（初期値 `部員`）、OB ロール名（初期値 `OB`）
- Discord.Net のログは `ILogger` に流す。

### README.md に書く権限（CLAUDE.md のルール）

- OAuth2 スコープ: `bot`、`applications.commands`
- Bot 権限: ロールの管理（Manage Roles）
- Gateway Intents: 特権 Intent は不要
- サーバー側の設定: Bot のロールを「部員」「OB」より上に並べる
- あわせて、トークンとサーバー ID の設定方法、起動方法を書く。

### 設計者の判断（ユーザー未確認・修正可）

- `/help` の一覧は、InteractionService が読み込んだコマンド（Bot 側の定義）から作る。Discord に問い合わせる必要がなく、Bot が知っているコマンドと一覧が必ず一致するため。
- 同じ名前のロールがサーバーに複数ある場合は、最初に見つかった1つを使い、ログに警告を出す。
- 設定されたサーバー ID に Bot が参加していない場合は、起動時にエラーログを出す。プロセスは落とさず、そのまま動き続ける。

### 実装者に任せること

- `/graduate` でロール更新を1回で行う具体的な方法。
- テストプロジェクトの構成とテストフレームワーク（ソリューション `mpcman_bot_v3.slnx` に追加すること）。

- Discord の3秒以内の応答制限に備えて返信を遅延応答（defer）にするかどうか。ただし、エフェメラル・公開の区別は上の仕様どおりにすること。
